# Бот для ветеринарных напоминаний (Go Version)

Telegram-бот для ежедневных напоминаний о ветеринарных процедурах (уколы, взвешивание). Написан на Go с использованием PostgreSQL и TiKV.

## Функциональность

- **Несколько питомцев**: каждый пользователь может добавить несколько питомцев и переключаться между ними.
- **Per-pet настройки**: для каждого питомца настраиваются дата начала цикла и время ежедневного напоминания.
- **Ежедневные уведомления**: отправка напоминаний в индивидуальное время для каждого питомца (по умолчанию 16:00 UTC).
- **Интерактивность**: каждое напоминание содержит кнопку «✅ Сделано!». Состояние укола сохраняется в базе данных и привязывается к вашему питомцу.
- **История веса**: команда `/weight` позволяет записывать и просматривать динамику веса питомца с пагинацией.
- **Настраиваемое место укола**: пользователь сам выбирает стартовую позицию для цикла уколов.
- **Защита от инъекций**: все пользовательские данные проходят валидацию через пакет `sanitize` (whitelist regex, проверка на SQL-паттерны).
- **Команды**:
  - `/start` — Приветственное сообщение.
  - `/help` — Список доступных команд.
  - `/add-pet [имя]` — Добавить питомца.
  - `/my-pets` — Список питомцев и выбор активного.
  - `/today` — Проверить статус укола на сегодня.
  - `/weight [число]` — Записать вес (например, `/weight 3.5`).
  - `/weight` — Показать историю записей веса.
  - `/injection-site` — Изменить стартовое место укола.
  - `/start-date ГГГГ-ММ-ДД` — Установить дату начала цикла для активного питомца.
  - `/reminder-time ЧЧ:ММ` — Установить время напоминания (UTC) для активного питомца.
- **Чередование мест для укола**:
  - Левая паховая
  - Левая лопатка
  - Правая лопатка
  - Правая паховая
- **Взвешивание**: Раз в 3 дня в напоминание добавляется заметка о взвешивании.
- **Изоляция данных**: система многопользовательская, любой может написать боту. Каждый пользователь видит только своих собственных питомцев, данные и уведомления полностью изолированы.
- **Надежность**: PostgreSQL для хранения данных, TiKV для KV-состояния и Trace ID в логах.

## Установка и запуск

### Подготовка

1. Скопируйте файл `.env.example` в `.env`:

    ```bash
    cp .env.example .env
    ```

2. Отредактируйте `.env`:
    - `BOT_TOKEN` — токен от BotFather.
    - `DATABASE_URL` — строка подключения к PostgreSQL.
    - `TIKV_PD_ADDRS` — адреса PD-серверов TiKV.

### Запуск через Docker Compose (Рекомендуется)

```bash
docker compose up -d --build
```

*Данные хранятся в Docker Volumes: `vet-pgdata` (PostgreSQL), `vet-pd-data` и `vet-tikv-data` (TiKV).*

### Проверка статуса (Healthcheck)

Бот предоставляет HTTP эндпоинт для мониторинга:

```bash
curl http://localhost:8081/health
```

## Разработка и тестирование

### Запуск тестов

```bash
go test ./... -v
```

Для тестов хранилища установите переменные окружения:

```bash
export TEST_DATABASE_URL="postgres://vet:vet@localhost:5432/vetdb?sslmode=disable"
export TEST_TIKV_PD_ADDRS="localhost:2379"
```

### Структура проекта

```text
vet-notifications-go/
├── cmd/bot/main.go           # Точка входа и HTTP healthcheck
├── internal/
│   ├── bot/                  # Логика Telegram (команды, кнопки, изоляция)
│   ├── config/               # Загрузка env (DATABASE_URL, TIKV_PD_ADDRS)
│   ├── kv/                   # TiKV хранилище (активный питомец)
│   ├── logger/               # Slog с поддержкой Trace ID и маскировкой токена
│   ├── reminder/             # Расчет мест уколов и форматирование текста
│   ├── sanitize/             # Валидация пользовательского ввода
│   ├── scheduler/            # Планировщик (тикер каждую минуту)
│   └── storage/              # PostgreSQL хранилище (pets, weights, injections)
├── Dockerfile                # Multi-stage сборка на базе scratch
└── docker-compose.yml        # Оркестрация: PD, TiKV, PostgreSQL, бот
```

## Технические особенности

- **PostgreSQL 18**: Реляционное хранилище для питомцев, веса и уколов. Per-pet `start_date` и `reminder_time`.
- **TiKV**: Распределённое KV-хранилище для состояния активного питомца.
- **Минимальный образ**: Итоговый контейнер на `scratch`.
- **Trace ID**: Каждое входящее сообщение получает уникальный ID в логах.
- **Graceful Shutdown**: Бот корректно завершает работу при получении сигналов SIGINT/SIGTERM.
- **Input Sanitization**: Все пользовательские данные (имена, даты, время, вес) валидируются через пакет `sanitize`.
